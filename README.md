# Zuyter Skin

چت‌بات پرسش‌وپاسخ پوست (فارسی). پاسخ‌ها فقط از اطلاعاتی می‌آید که خودتان در دیتابیس می‌گذارید (RAG ساده بدون هزینه‌ی مدل).

## ساختار

| مسیر | کار |
|---|---|
| `docs/index.html` | سایت (یک فایل، بدون وابستگی). با GitHub Pages منتشر می‌شود |
| `supabase/migrations/` | ساختار دیتابیس (جدول‌ها، جستجو، امنیت) |
| `supabase/seed.example.sql` | نمونه‌ی ردیف برای دیدن ساختار داده |

## چطور کار می‌کند

1. مشتری سؤال می‌نویسد، سایت تابع `ask_skin` را در Supabase صدا می‌زند.
2. متن فارسی نرمال می‌شود (ي→ی، ك→ک، حذف اعراب و نیم‌فاصله و کلمات رایج) و با جدول `knowledge` مقایسه می‌شود (`pg_trgm`).
3. اگر جوابی پیدا شد، نمایش داده می‌شود. اگر نه، سؤال در جدول `unanswered` ذخیره می‌شود تا جوابش را اضافه کنید.

## اضافه کردن اطلاعات

در داشبورد Supabase، جدول `knowledge` را باز کنید و ردیف اضافه کنید:

- `question`: سؤال
- `answer`: جواب
- `keywords`: شکل‌های دیگر پرسیدن و کلمات مرتبط (روی کیفیت جستجو خیلی اثر دارد)
- `category`: دسته‌بندی (اختیاری)

سؤال‌های بی‌پاسخ را در جدول `unanswered` ببینید (ستون `hits` یعنی چند بار پرسیده شده).

## امنیت

- جدول‌ها RLS دارند و از بیرون قابل خواندن نیستند.
- سایت فقط می‌تواند تابع `ask_skin` را صدا بزند.
- کلید داخل `index.html` کلید عمومی (publishable) است و مخفی نیست. کلید سرویس (`service_role`) را هرگز در این ریپو نگذارید.
- اطلاعات و جواب‌های اصلی در Supabase است، نه در این ریپوی عمومی.
